Git 介紹與指令說明

2026-04-07 更新於 2026-05-21 git
git

📢 Git 是分散式版本控制系統，通過提交、分支、合併機制追蹤檔案變更，支持多開發者協作、版本管理和代碼審查。

🔥 git 常見相關檔案

  • .git 目錄 : 重要 ，用於紀錄版管理資訊
  • .gitignore 檔案 : 用於設定哪些檔案或目錄不需版本控制
  • README 檔案 : 用於撰寫自定義的專案使用說明或用途述說等
  • LICENSE 檔案 : 用於說明開源專案的授權條約和相關使用規範

git pull 等同執行 git fetch +git merge

  • git fetch : 拉取遠端儲存庫對應分支的更新資訊。
  • git merge : 將拉取的更新資訊跟本地對應分支合併。

  • git rebase : 另一種合併方式 ，將當前分支的新版本紀錄移動到合併的對應分支版本修改之後，使版本紀錄加簡潔。

🔥 git 版本回退

常用版本號範例
哈希值a1b2c3d，(通常取前7位 )
指標HEAD，(代表最新提交版本 )、 HEAD^1，(上一次提交版本 )、 HEAD~1，(上一次提交版本 )
分支origin/test，(遠端test分支的最新版本 )、 test2，(本地test2分支的最新版本 )
回退方式使用場合推版影響版本歷史可用版本號
git checkout (git restore、git switch )將文件內容切換為指定版本的內容，通常用於暫時性的回退需將版本復原才可繼續提交或拉取新版本不改變版本歷史哈希值、指標、分支(最新版本)
git reset將最新版本到指定版本間的任何修改丟棄，通常用於需完全丟棄版本歷史使用可直接提交新版本改變版本歷史哈希值、指標、分支(最新版本)
git revert將指定版本的修改在新版本中反向復原，通常用於棄用某分支在合併的修改 或 棄用指定版本間的修改可直接提交新版本不改變版本歷史哈希值、指標，不可用分支

⭐git reset 回退

  • 軟回退 : 回退時，保留工作區/暫存區 的修改
  • 混合回退 : 回退時，保留工作區，暫存區移出 ，預設
  • 硬回退 : 回退時，刪除工作區/暫存區 的修改，使用時注意，就算復原，工作區/暫存區也不會復原
