Grafana 介紹

2026-05-02 更新於 2026-06-11 監控管理
grafana DevOps 日誌管理

📢 Grafana 是一個開源的資料可視化平台 ，可將各種數據來源（Prometheus、Elasticsearch、MySQL 等）的指標以圖表、儀表板形式展示，是現代監控系統的標配工具。

⭐️ 支援的資料來源類型

  • 時間序列資料庫

    • Prometheus - 主流開源監控
    • InfluxDB - 高效時間序列資料庫
    • Graphite - 分散式監控系統

  • 日誌聚合平台

    • Loki - Grafana 官方日誌系統
    • Elasticsearch - 分散式搜尋引擎
    • Splunk - 企業日誌分析

  • 關聯式資料庫

    • MySQL / MariaDB
    • PostgreSQL
    • Microsoft SQL Server

  • 其他資料來源

    • Google Cloud Monitoring
    • AWS CloudWatch
    • Azure Monitor
Info
各資料來源的連線參數應按實際部署進行調整，確保網路連接暢通。建議使用容器內部服務名稱（如 http://prometheus:9090 ）而非 localhost。

📊 儀表板建立

⭐️ 透過 UI 建立儀表板

  1. 登入 Grafana（預設 http://localhost:3000 ）
  2. 左側選單點擊 Dashboards
  3. 按下
    • New Dashboard
    按鈕
  4. 選擇 Add a new panel 或 Add a new row
  5. 選擇資料來源和查詢語言（如 PromQL、SQL）
  6. 自訂視覺化類型和樣式
  7. 設定告警規則（可選）
  8. 保存儀表板

⭐️ 常見面板類型

面板類型適用場景示例指標
Graph / Time Series顯示時間序列趨勢CPU 使用率、記憶體用量
Gauge顯示當前值的百分比磁碟使用率、電池電量
Stat顯示單一數值或比較當前在線用戶數、總請求次數
Bar Chart比較不同類別的數值各節點 CPU 排名、服務響應時間
Pie Chart展示部分與整體的比例錯誤率分佈、流量來源比例
Heatmap展示二維數據密度請求延遲分佈、並發用戶熱力圖
Logs顯示日誌內容（需 Loki）應用日誌、系統事件
Table以表格形式展示資料服務列表、配置清單
Info
面板配置中可使用變數（$variable )，允許使用者動態篩選資料。常見變數包括時間範圍、主機名稱、服務名稱等。

🔔 告警平台設定

⭐️ 支援的通知方式

Grafana 支援多種告警通知平台：

  • 即時通訊工具

    • Telegram - 輕量即時通知
    • Slack - 團隊協作通知
    • Discord - 社群伺服器通知

  • 郵件系統

    • Email - SMTP 協議發送告警

  • 企業整合

    • PagerDuty - 事件管理服務
    • Opsgenie - 告警聚合平台

  • 自訂集成

    • Webhook - 發送 HTTP 請求至自訂端點

⭐️ Telegram 通知設定

第 1 步：建立 Telegram Bot

  1. 在 Telegram 搜尋 @BotFather
  2. 發送指令 /newbot
  3. 按照指示輸入機器人名稱，取得 Bot Token

第 2 步：取得 Chat ID

第 3 步：Grafana UI 設定

在 Grafana UI 左側選單選擇 Alerting → Notification Channels ：

  1. 點擊
    • New channel
  2. 名稱：Telegram Alert
  3. 類型：Telegram
  4. 填入 Bot Token 和 Chat ID
  5. 點擊 Test 確認配置
  6. 保存

⭐️ Slack 通知設定

第 1 步：建立 Slack Webhook

  1. 前往 Slack App Directory，搜尋 Incoming Webhooks
  2. 選擇工作區並點擊 Install
  3. 選擇通知通道（如 #alerts ）
  4. 複製 Webhook URL

第 2 步：Grafana UI 設定

在 Grafana 通知頻道設定：

  1. 點擊
    • New channel
  2. 名稱：Slack Alert
  3. 類型：Slack
  4. 填入 Webhook URL
  5. 選擇傳送方式（POST 至 Slack）
  6. 測試並保存

⭐️ Discord 通知設定

第 1 步：建立 Discord Webhook

  1. 進入 Discord 伺服器設定 → Webhooks
  2. 點擊 Create Webhook
  3. 選擇通知頻道，複製 Webhook URL

第 2 步：Grafana UI 設定

  1. 點擊
    • New channel
  2. 名稱：Discord Alert
  3. 類型：Discord （如果沒有，使用 Webhook ）
  4. 填入 Webhook URL
  5. 測試並保存

⚠️ 告警規則設置

⭐️ 建立告警規則

在儀表板的面板中設定告警：

  1. 點擊面板的 Edit 按鈕
  2. 進入 Alert 標籤
  3. 設定 Alert name （告警名稱）
  4. 定義告警條件（如 CPU > 80%）
  5. 設定告警持續時間（如 5 分鐘內都超出閾值才觸發）
  6. 選擇通知頻道
  7. 新增告警訊息和標籤
  8. 保存面板

⭐️ 告警規則配置範例

⭐️ 告警規則最佳實踐

  • 設定適當的告警閾值

    • 避免過敏感的閾值導致告警風暴
    • 根據歷史資料和系統特性調整

  • 使用分級告警

    • warning - 可忍受的狀態，監控即可
    • critical - 需要立即處理的狀況

  • 新增有意義的告警訊息

    • 清楚描述問題
    • 提供解決步驟或文件連結

  • 定期審查告警規則

    • 刪除不必要的告警
    • 調整過時的閾值
Danger
過多的告警會導致告警疲勞，團隊會開始忽視告警。應定期審查告警有效性，保持告警信號清晰。

📝 Loki 日誌管理

⭐️ Loki 簡介

Loki 是 Grafana 官方開發的日誌聚合系統，設計目標是輕量級、高效能。與 ELK Stack 相比，Loki 占用資源更少。

  • 核心特點
    • 輕量級標籤索引，不索引日誌內容
    • 與 Prometheus 標籤系統相同，易於統一管理
    • 支援 LogQL 查詢語言（類似 PromQL）
    • 完全開源，社群活躍

⭐️ 預設面板配置

常見的高效監控儀表板應包含以下面板：

  • 系統概況

    • CPU 使用率（Gauge 面板）
    • 記憶體使用率（Gauge 面板）

    • 錯誤日誌數量趨勢
    • 警告訊息排序
    • 訪問日誌分佈

  • 告警狀態

    • 當前告警列表
    • 告警歷史熱力圖
    • 告警恢復時間統計
