Docker 介紹與使用

2026-04-05 更新於 2026-05-21 container
docker docker compose

📢 Docker 是開源容器化平台，通過容器化隔離技術實現應用的獨立性、可移植性和輕量化，支持鏡像構建、容器編排，讓開發和運維更加高效。

  • 使用 Docker 原因
    • 開發到生產環境一致性
    • 應用程式環境隔離
    • 易於管理和擴展
    • 可移植性高
    • 輕量性

🚀Docker 設定相關和指令說明

⭐Docker 日誌驅動

Docker 支援多種日誌驅動程式，允許使用者根據需求選擇日誌的輸出方式。Docker 日誌驅動決定了容器日誌如何被收集、儲存和傳遞。預設情況下，Docker 使用 json-file 驅動。

  • json-file ：預設的日誌驅動，日誌以 JSON 格式儲存在宿主機上。預設日誌驅動會因容器刪除而跟著刪除日誌，其它日誌驅動則會保存至對應服務不會因此刪除 。
    • 通常位於 /var/lib/docker/containers/<容器ID>/<容器ID>-json.log
  • syslog ：將日誌發送到系統的 syslog 服務，適合集中式日誌管理。
    • Debian/Ubuntu 系統 上通常位於 /var/log/syslog
    • RHEL/CentOS 系統 上通常位於 /var/log/messages
    • 其它系統 上通常位於 /var/log/daemon.log、/var/log/containers/
  • journald ：將日誌發送到 systemd 日誌服務。
    • 通常使用指令
  • fluentd ：將日誌發送到 Fluentd 服務，通常用於集中式日誌收集和處理。
  • awslogs ：將日誌發送到 AWS CloudWatch。
  • gelf ：將日誌發送到 Graylog。
  • splunk ：將日誌發送到 Splunk 服務。

⭐Cgroups 資源管理

Cgroups 是 Linux 內核的一項功能，用於限制、計量和隔離進程的資源（如 CPU、記憶體、I/O 等）。Docker 使用 cgroups 來控制和限制容器的資源使用。一般會和其它使用容器相關的服務(如 k8s)配置相同的驅動方式，以達到資源管理一致性來避免資源爭用、監控和調度的問題 。

  • Docker 預設安裝 Cgroups 的驅動是 cgroupfs

  • 更改為 systemd 做為 Cgroups 的驅動:

    • 修改 /etc/docker/daemon.json （如果檔案不存在，可直接創建）
    • 重啟 Docker 服務使其生效
    • 查看目前 Cgroups 驅動方式

⭐Docker 相關

  • 資源限制 Docker 容器默認情況下沒有明確的資源限制 ，代表著容器可以根據需要使用宿主機的所有可用資源(CPU、記憶體、硬碟/IO、網路頻寬等)，直到宿主機資源耗盡為止。

  • docker 指令使用 默認情況下，Docker 守護進程（Docker Daemon）需要 root 權限來運行，因為它需要直接訪問系統資源（如網絡、檔案系統、進程等）。因此一般用戶如果要使用通常要加上 sudo ，除非把該用戶加進 docker 群組。

  • 容器終端
映像類型容器終端
Debian/Ubuntu 、RHEL/CentOS 基礎映像/bin/bash
Alpine 基礎映像，輕量 Linux 發行版/bin/sh
  • 容器訪問主機服務 容器中不能直接透過 127.0.0.1:PORT 來訪問主機對應服務，通常會使用外網ip 訪問或 host.docker.internal 。

⭐Docker 指令介紹

自定義範例 Dockerfile

  • Dockerfile 常用語法
    • FROM : 指定映像檔的基礎映像。後面通常會搭配 AS 來定義階段，使用參數為 –target
    • RUN : 通常用於容器建構中的前置執行指令
    • ENTRYPOINT : 容器啟動後一定會執行指令
    • CMD : 容器啟動後執行指令，搭配 ENTRYPOINT 使用為提供指令參數，會被 docker run 接續指令覆蓋
    • COPY : 本地資料放置建置容器中
  • ADD : 基本跟COPY相同，但可以把解壓縮檔解壓後複製到指定目錄中
  • ENV : 設定環境變數
  • ARG : 設定建構時參數
  • WORKDIR : 設定容器裡的工作目錄，不存在會自行創建，後續指令都會在此目錄下執行
