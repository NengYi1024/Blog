K8S 介紹與使用

2026-04-10 更新於 2026-05-31 container
docker k8s kustomize

📢 Kubernetes （簡稱K8S ）是容器編排平台，提供自動部署、自動擴展、負載均衡等功能，適用於微服務架構和分散式應用。

🚀K8S 介紹

  • 主要特點
    • 自動化部署和管理
    • 高可擴展性
    • 容器管理
    • 服務串聯與負載平衡
    • 滾動更新與回退
    • 資源管理
    • 自動恢復機制

在 Kubernetes 中，Cluster、Node、Pod 是三個核心概念，它們是構建和管理 Kubernetes 集群的基本單位 。

  • Pod : 是 Kubernetes 中最小的部署單位 ，一個 Pod 可以包含一個或多個容器。
  • Node : 是 Kubernetes 集群中的工作機器，可以是實體/虛擬機 或 serverless 服務 。
  • Cluster : 是由多個 Node 組成的集合 ，Kubernetes 控制平面管理和協調集群中的所有節點和資源。

⭐K8S 常用資源

種類說明
Podk8s 中的基本單位 ，用來運行容器化的應用。透過 deployment 設定創建，或單獨建立 。
Deployment用來管理 Pod 的創建和設定 。
Service透過選用 Pod 綁定的標籤 ，來使 k8s 集群內的 pod 可以相互溝通 。
Ingress用來管理外部訪問 k8s 集群 內的方式。也可使用 Service 配置 LoadBalancer 類型來替代 Ingress 使外部訪問集群內對應服務 。
使用前要搭配 Ingress Controller 使用 常用 Ingress 控制器如下 :
  • NGINX Ingress 控制器
  • AWS ALB Ingress 控制器
  • APISIX Ingress 控制器
  • HAProxy Ingress 控制器
ConfigMap通常用於覆寫容器內原始設定 用。讓容器可動態更新設定，而不用重新建構容器鏡像 。推薦使用 kustomization.yaml 設置 configMapGenerator 來使用完整設定檔，以防止檔案格式錯誤 。
Secret用來存儲敏感資料，以供容器安全讀取使用。
PersistentVolume (PV)用儲存持久化數據使用。
PersistentVolumeClaim (PVC)讓 Pod 透過 PVC 來使用對應 StorageClassName 的 PV 。
StorageClass對應 StorageClassName 的 PV 不存在時，會 根據 StorageClass 設定動態創建 PV 。
CronJob用於執行定時任務的資源。
StatefulSet用於使 Pod 重啟、擴容、縮容或升級時，仍保留相同的狀態(DNS、名稱)等，適用於需有序啟動、停止或升級的應用。
Namespace用來將 k8s 集群中的資源進行邏輯分組，使多個應用環境共享同一個集群 。未使用時，會將資源部署到默認的 namespace ( default )中 。
  • Pod、Deployment 和 Service : Deployment 設定副本創建多個 Pod，Service 再透過取用 Pod 標籤來使其它 Pod 間相互溝通。
  • Ingress : 透過配置 Ingress Controller 來管理外部訪問 k8s 集群內的方式
  • PersistentVolume (PV)、PersistentVolumeClaim (PVC) : 說明對應關係和動態/靜態綁定 PV 的差異。
  • Namespace : 使用不同 Namespace 來區隔同一個 k8s 集群內的應用。

⭐K8S 資料儲存方式

儲存類型說明使用環境
hostPath透過掛載節點的目錄來儲存資料只能在掛載的節點上使用
local透過掛載節點的硬碟空間來儲存資料只能在掛載的節點上使用
CSI (容器儲存接口)透過掛載外部儲存服務或設備來儲存資料(AWS EBS、AWS EFS、GCE Persistent Disk、Ceph、NFS 等 )，使用前需安裝對應CSI驅動可跨節點和跨集群使用
emptyDir跟隨對應的 Pod 啟動和刪除，掛載節點上，適用於同節點 Pod 臨時共用資料只能在掛載的節點上使用

🚀K8S 搭建方式差異

⭐自建 k8s (不推薦)

  • 管理方面 :
    1. 節點機器管理 : 需自行配置機器、網路、儲存空間等。
    2. 集群控制管理 : 需自行管理主節點和工作節點的溝通。
    3. k8s 版本管理 : 需自行升級 k8s 版本。
    4. 安全性管理 : 需自行對網路安全和不同使用者權限管理。
    5. 負載和擴展管理 : 需自行搭建擴展節點和處理負載問題。
    6. 監控和日誌管理 : 需自行創建監控和日誌管理流程。
    7. 成本管理 : 需自行處理成本策略。
  • 部署流程 :
    1. 節點機器準備 : 通常準備一台 master 節點，多台 worker 節點，linux 環境。
    2. 安裝 k8s 相關工具 (所有節點 ) : 安裝 kubeadm、kubelet、kubectl 還有容器服務(docker、containerd、CRI-O)。
    3. 初始化 Master 節點 (master 節點 ) : 使用 kubeadm init 在 master 節點 上初始化 k8s 集群。
    4. 配置 kubectl 設定 (master 節點 ) : 在 master 節點上配置 kubectl 設定(kubeconfig 檔案)，使其可以訪問集群。
    5. 部署容器網絡插件 (master 節點 ) : 在 master 節點上部署容器網絡插件，如 Flannel、Calico 等，讓 Pod 可以溝通。
    6. 將 Worker 節點加入集群 (worker 節點 ) : 在 worker 節點上執行 kubeadm join 命令，將其加入到 k8s 集群中。在 master 節點初始化後操作。
    7. 檢查集群狀態 (master 節點 ) : 在 master 節點上使用 kubectl 檢查集群的狀態，確保節點已經成功加入集群。
    8. 部署應用和設置監控 (master 節點 ) : 在 master 節點上使用 kubectl 創建和管理應用，還有配置集群的監控和日誌收集工具。

⭐雲端服務創建 k8s (AWS EKS )

  • 管理方面 :
    1. 節點機器管理 : 透過 AWS 自動管理 。
    2. 集群控制管理 : 透過 AWS 自動管理 。
    3. k8s 版本管理 : 透過 AWS 自動管理 。
    4. 安全性管理 : 搭配 AWS IAM 和網絡安全功能，簡化身份驗證和權限管理。
    5. 負載和擴展管理 : 透過 AWS EKS 自動支持彈性擴展功能，實現自動負載功能。
    6. 監控和日誌管理 : 搭配 AWS 工具簡化集成監控和日誌管理。
    7. 成本管理 : 透過 AWS 成本計費，並可對集群中不同應用分割費用 。
  • 部署流程 :
    • 使用 kubectl、AWS CLI 或其它 AWS 管理工具 簡化以下部署流程 :
      1. 節點機器準備 : 可選 EC2 或 Fargate (serverless 節點)。
      2. 安裝 k8s 相關工具 : 節點預設安裝 kubeadm、kubelet、kubectl，容器服務預設安裝 containerd 。
      3. 初始化 Master 節點 : 創建時自動初始化。
      4. 部署容器網絡插件 : 預設使用 CNI 網路插件。
      5. 將 Worker 節點加入集群 : 創建時自動加入集群。
